Source release readiness

Reviewed 6 September 2026. This gate covers a source archive generated by git archive; it does not cover a local evidence directory, MP snapshot, candidate-level ranking bundle, dependency environment or production Seko database.

Ordered pre-tag checklist

Run this checklist from the repository root. The candidate is the exact commit printed in step 1; do not tag it if HEAD changes, the working tree becomes dirty, or any later step fails. Start again from step 1 instead.

  1. Freeze and identify the candidate:
    git status --short
git rev-parse HEAD
git branch --show-current
    Require an empty status and the intended release branch. Record the full commit SHA in the release notes.
  2. Run the Julia package gate:
    julia --startup-file=no --project=. -e 'using Pkg; Pkg.test()'
  3. Run the Python gate:
    python3 -m unittest discover -s test -p 'test_*.py'
  4. Audit the archive made from the candidate commit, retaining the audit outside the repository:
    candidate=$(git rev-parse HEAD)
python3 scripts/verify_release.py --archive "$candidate" --output /tmp/eka-release-audit.json
    Require "status": "pass" and an empty problems list.
  5. Push that commit and require every job in its GitHub Actions run to pass, including Documentation. Confirm that the development manual is reachable at https://JoshCCorby.github.io/EkaCompositions.jl/dev/.
  6. Immediately before tagging, repeat step 1 and require the recorded SHA and clean status to be unchanged. The tag must point to that SHA.

Findings from the 6 September 2026 review

The post-documentation candidate was clean before review. The three local gates passed:

  • Julia 1.12.6: 4,756 of 4,756 assertions passed.
  • Python 3.14.6: all 36 discovered tests passed.
  • The exact-commit archive audit passed with an empty problems list.

GitHub Actions run 34040718639 passed for the same source tree: Julia 1.10 and current Julia passed on Ubuntu, current Julia passed on macOS and Windows, the analysis and exporter jobs passed on Python 3.11–3.14, and the Documentation job built and deployed the manual. GitHub Pages is configured to publish / from the gh-pages branch with HTTPS enforced.

These findings establish source-release readiness only. They do not create a tag or GitHub release, and they do not approve publication of any local research artifact.

Candidate contents

The source candidate contains Eka's Julia and Python source, methodological documentation, synthetic examples, tests, the small noticed Seko-derived fixture, aggregate prose findings, MIT licence, third-party notices and citation metadata. Git archive attributes exclude local activity logs. Ignored local data and evidence directories are not members of the archive.

The aggregate findings identify Materials Project as the data source, database version 2026.04.13, retrieval time, transformations, GNoME exclusion, citation and non-endorsement limitation. No material IDs, candidate-level rankings, factors, MP snapshots, API keys or complete dependency environments are included.

Archive gate details

The audit builds the actual Git archive and fails on:

  • local data, report or activity-log paths;
  • unreviewed JSONL/SQLite/database files, except the documented tiny fixture;
  • environment files and Manifest.toml;
  • symbolic links, hard links and other special archive members;
  • private-key markers and common GitHub, AWS and literal MP API-key forms;
  • machine-specific home paths, files over the review limit, missing licence, notice/citation metadata, or absent MP/Seko attribution.

The JSON output records every regular archive member's type, mode, size and SHA-256 plus a manifest hash. It is a content-control aid, not a guarantee that arbitrary secrets or all legal issues can be recognized automatically. CI runs the audit and its focused tests on every push and pull request.

Terms and decision

The terms evidence now includes a read-only check of the live official MP page on 31 August 2026. That page confirms CC BY 4.0 for MP Content with credit, licence link and change indication, and separately assigns GNoME CC BY-NC 4.0. The project excluded GNoME. MP asks users to contact it for guidance before repackaging and publicly redistributing MP data.

The source-only archive is ready as a release candidate because it does not repackage record-level MP data and retains the relevant attribution and notices. No tag, GitHub release or data publication is performed by this review. A future MP data/results bundle must receive a separate file-by-file review and may warrant provider guidance based on its concrete contents.
